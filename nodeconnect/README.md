# NodeConnect

Keeps the equipment and settings of two or more Galileo computers in step with a **Master** over Connect Link, sends
images to the Master in the background, and lets a computer fetch an image back when it needs one.

- Scope, requirements and design: [`docs/plugins/nodeconnect/`](https://github.com/gordtulloch/Galileo/tree/main/docs/plugins/nodeconnect) in the Galileo repository (PSD, SRS, SDD, RTM).
- For users: the wiki article *17. NodeConnect*; every control on **Options > NodeConnect** has built-in help.
- Wire: `/nodeconnect/v1`, described in [`api/nodeconnect-v1.openapi.json`](api/nodeconnect-v1.openapi.json) (generated by `python -m nodeconnect.openapi`; a test fails if it drifts).

## What it does

| Area | Module |
|---|---|
| Spoke, Master or standalone, derived from facts | `roles` |
| Pairing with a confirmation code (core's Connect Link pairing) | `pairing` |
| Which tables and fields replicate; secrets and node-local values never do | `repl`, `codec` |
| Sync: pull, push, arbitration, tombstones, acknowledgements | `sync`, `master`, `conflict`, `compat`, `wire`, `link` |
| Apply when no session is running; snapshots; undo | `apply`, `store`, `reports` |
| Master tells nodes there is something to pull | `push` |
| Frames to the Master, checked on arrival; fetch back on demand | `transfer`, `ingest`, `frames`, `history` |
| Notifications | `alerts` |
| Status view and the Options page | `status`, `ui` |

## Developing

Python 3.11, with Galileo installed in the same environment (`pip install -e ../../Galileo`):

```
python -m pytest tests                  # 80 tests, about 30 s
python -m pytest tests -m integration   # the Master in its own process, over real TLS
python -m ruff check .
python build_zip.py                     # builds dist/; do not commit the plugins.json change it may make
```

`tests/test_ncon_spec.py` has a document-chain test that reads the SRS and RTM in the sibling Galileo checkout and fails
if a requirement has no RTM row or an RTM test case has no test.
